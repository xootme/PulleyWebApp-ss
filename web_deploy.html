How It Works

GreenGeeks uses LiteSpeed as the web server. LiteSpeed does not support WSGI natively, so a CGI bridge is used to translate web requests into the format Flask understands. Every request goes through this chain:

Browser
HTTP request
→
LiteSpeed
web server
→
index.cgi
CGI bridge
→
wsgiref
WSGI adapter
→
app.py
Flask app
Subfolder note: The app lives under /tst_pulleys/, not the domain root. index.cgi sets SCRIPT_NAME=/tst_pulleys so Flask generates correct URLs for CSS, JavaScript, and image assets automatically.
2

Deployment Files

Three files handle the entire deployment pipeline:

File Runs On Purpose
index.cgi server Server LiteSpeed entry point. Activates the venv, sets SCRIPT_NAME, and hands off to Flask via wsgiref. Must be chmod 755.
provision_remote.sh server Server Creates the virtual environment, installs all Python dependencies, sets file permissions, and verifies the install. Run once after first upload, and again whenever requirements.txt changes.
deploy.sh local Local (Git Bash / WSL) Syncs project files to the server via rsync, then SSH-triggers provision_remote.sh automatically. One command does a full deploy.

First-Time Setup

  • 1
    Upload the project files to the server

    Use the deploy script from Git Bash on your Windows machine. Open Git Bash, navigate to the project folder, and run:

    Git Bash — project root
    # Full deploy: sync files + run provisioner
bash deploy.sh
  • 2
    Provisioner runs automatically

    deploy.sh SSH-triggers provision_remote.sh on the server. It creates the Python virtual environment, installs Flask, Pillow, and ezdxf, and sets chmod 755 on index.cgi. You will see output like:

  Provisioning complete.

  • 3
    Verify in the browser

    Open https://cheapcadtools.com/tst_pulleys/ — the pulley generator should load with the full UI.

Routine Deploys (After Code Changes)

What ChangedCommandNotes
Python code, exporters, geometry bash deploy.sh Full sync + provisioner. Safe to run every time.
Templates, static files (HTML/CSS/JS) bash deploy.sh --sync Sync only — skips the provisioner (faster).
requirements.txt changed bash deploy.sh Must run provisioner so new packages are installed in the venv.
What deploy.sh excludes (never uploaded)
venv/          # server builds its own venv
__pycache__/   # compiled bytecode
*.pyc
tests/         # unit tests not needed on server
*.md           # documentation
deploy.sh      # local script only
testing.html   # local dev file

GitHub Source Control

The project is stored in a private GitHub repository at github.com/xootme/PulleyWebApp. Always commit and push to GitHub before deploying to the server — GitHub is the source of truth.

One-time setup (Git Bash, project root)
git init
git add .
git commit -m "Initial commit — Sketch Timing Pulley Generator"
git remote add origin https://github.com/xootme/PulleyWebApp.git
git push -u origin main
Normal commit workflow
git add .
git commit -m "describe what changed"
git push
Recommended deploy sequence
# 1. Save your work to GitHub
git add .
git commit -m "your message"
git push

# 2. Push to production server
bash deploy.sh
Authentication: GitHub no longer accepts account passwords over HTTPS. Use a Personal Access Token when Git prompts for a password.
GitHub → Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token → check repo scope.

Manual SSH Commands

If you need to run steps individually (e.g. debugging or partial update):

SSH into the server
ssh xootpro@chi203.greengeeks.net
Sync files only (no provisioner)
rsync -avz \
  --exclude 'venv/' --exclude '__pycache__/' --exclude '*.pyc' \
  --exclude 'tests/' --exclude '*.md' --exclude 'deploy.sh' \
  ./ xootpro@chi203.greengeeks.net:~/public_html/cheapcadtools/tst_pulleys/
Run provisioner on server
ssh xootpro@chi203.greengeeks.net \
  "bash ~/public_html/cheapcadtools/tst_pulleys/provision_remote.sh"
One-liner: sync + provision
rsync -avz --exclude 'venv/' --exclude '__pycache__/' --exclude '*.pyc' \
  --exclude 'tests/' --exclude '*.md' --exclude 'deploy.sh' \
  ./ xootpro@chi203.greengeeks.net:~/public_html/cheapcadtools/tst_pulleys/ \
&& ssh xootpro@chi203.greengeeks.net \
  "bash ~/public_html/cheapcadtools/tst_pulleys/provision_remote.sh"
Fix permissions manually (if 500 error after upload)
ssh xootpro@chi203.greengeeks.net \
  "chmod 755 ~/public_html/cheapcadtools/tst_pulleys/index.cgi"

Troubleshooting

SymptomLikely CauseFix
500 Internal Server Error index.cgi not executable chmod 755 index.cgi on server — or re-run provisioner
CSS / JS not loading (404) Wrong SCRIPT_NAME or static path Confirm SCRIPT_NAME=/tst_pulleys is set in index.cgi
ModuleNotFoundError Venv not activated or dep missing Re-run provision_remote.sh
Blank page / import error Python version mismatch Confirm /opt/alt/python311/bin/python3 exists on server
ezdxf missing New dependency not yet installed Re-run provision_remote.sh (installs from requirements.txt)
Images / previews broken Pillow missing or wrong arch Re-run provisioner; check pip install pillow output for errors
Old code still showing Browser cache or rsync skipped files Hard-refresh browser (Ctrl+Shift+R); confirm rsync output shows updated files
Important: The venv is never synced from local to server. Always build it on the server by running provision_remote.sh. Uploading a local venv will cause binary compatibility errors on Linux.
8

How app.py Handles the Subfolder

When index.cgi sets SCRIPT_NAME=/tst_pulleys, app.py detects this environment variable at startup and automatically applies ProxyFix middleware. This means:

  • Static asset URLs (/static/style.css) resolve correctly under the subfolder
  • Flask redirects include the /tst_pulleys/ prefix
  • API endpoints (/api/preview, /download/svg, etc.) all work
  • No change is needed for local development — the env var is absent locally so Flask runs normally on localhost:5000
